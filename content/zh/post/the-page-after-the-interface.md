主题自带的测试页里塞满了标题、列表、代码块、表格和数学公式。建站的时候它很有用，读起来却像一张验收清单。那些例子底下有个更值得追问的问题：把界面、网络和额外脚本拿走之后，页面还剩下什么？

标题仍然要清楚，正文仍然要好读，对比度要够，键盘也要能走到页面的每个部分。打印出来时，论证不能散。JavaScript 失效时，内容也要能读。

## Markdown 做骨架

大多数文章用 Markdown 写。标题会进目录，引用块留下出处，代码围栏保住缩进，表格适合放一组短对照。这些结构容易搜索，也容易翻译。

I 只在 Markdown 说不清楚结构时写 HTML。这个站点允许用原始 HTML 做题图、折叠内容和少数需要全屏嵌入的页面。把许可收窄，例外才容易找。

行内代码和正文有区别，长代码块有自己的背景和横向滚动。窄屏时，代码只在自己的容器里移动，不会把整页撑宽。

## 页边也会说话

受 Tufte 排版影响的文章，会用旁注放一句插话。旁注适合读者可以跳过、又不影响正文理解的内容。如果这条注改变论证，它应该回到正文。

短补充用 `marginpar`，需要作者和出处的引文用 `epigraph`。两者都保持为排版的一部分，不再变成另一些漂浮的面板。

## 数学公式不该被某个库绑住

有些公式用 MathML 写，这样即使数学排版库没有加载，公式仍然留在文档里。KaTeX 和 MathJax 也能处理更复杂的排式，但它们会带来样式表或脚本。只有需要那部分排版的页面才应该付出这份成本。

这和页面里的其他选择一样：先用原生 HTML，结构不够时用 shortcode，只有正文确实写不清楚，才加载更大的工具。

## 测试就是试读

新页面会在宽窗口和 390 像素宽度各看一遍。我会切换深浅配色，放大字号，打开无障碍面板，用键盘走过标题，再单独读链接文字。图片承载信息时写说明，纯装饰就让它退出无障碍树。

这些检查不能保证每个人看到完全一样的页面。它们能找出那些明显的时刻：页面不再是页面，而只是脚本的容器。

最后一关是打印。页边、图注和代码块落到纸上还能看懂，结构通常就没问题。

界面退场之后，页面仍然应该可以读。
