即使 JavaScript、外部脚本或高级布局不可用，文章正文也应保持可读。因此站点从语义化 HTML 开始，只在交互确实有用时增加脚本。

## 使用 Markdown 表达文档结构

大多数文章使用 Markdown。生成的 HTML 包含导航和辅助技术所依赖的结构：

- 标题生成目录。
- 引用块标识引文。
- 代码围栏保留缩进和语言信息。
- 表格用于结构固定的短对照。

这些元素不依赖自定义渲染逻辑，也可以搜索、翻译和打印。

Markdown 无法表达所需结构时可以使用原始 HTML。本站只把它用于图表、折叠内容和少数全屏嵌入页面。控制原始 HTML 的使用范围，便于检查这些例外。

行内代码使用独立样式。长代码块在自己的容器内横向滚动，不会在窄屏上撑宽整个页面。

## 旁注

Tufte 风格旁注用于放置会打断主段落的短补充。旁注是可选内容，读者跳过它后仍能理解正文。如果旁注会改变论证，应把它放回正文。

短补充使用 `marginpar`。需要作者和出处的引文使用 `epigraph`。两者都属于文档排版，不会打开额外的交互面板。

## 原生数学公式与可选渲染器

部分公式使用 MathML，因此数学渲染器未加载时，公式仍保留在 HTML 中。需要特定排版效果时，页面可以使用 KaTeX 或 MathJax，但会增加该页面的 CSS 或 JavaScript。

加载顺序如下：

1. 原生 HTML 足够时直接使用。
2. 文档结构需要额外表达时使用 shortcode。
3. 原生 HTML 无法清楚表达公式时，才加载 KaTeX 或 MathJax。

## 响应式行为

窄屏下保持阅读顺序。标题和正文保持单栏，导航进入现有菜单控件，图片不会造成横向滚动。代码行过长时，代码块在自身容器内滚动。

## 无障碍与打印检查

发布前在宽屏浏览器和 390 像素视口中检查页面。当前检查表包括：

- 浅色和深色配色
- 低、默认和高对比度
- 字号调整
- 使用键盘遍历标题和控件
- 脱离上下文阅读链接文字
- 信息图片的替代文字
- 装饰图片不进入无障碍树
- 禁用 JavaScript 时的文档顺序
- 标题、图注、代码和旁注的打印布局

这些检查不能证明所有浏览器和辅助技术都会得到相同结果。它们可以发现内容模型、阅读顺序和布局方面的回归。

## 构建检查

发布前执行完整检查：

```bash
npm run check
npm run build
npm run check:links
```

第一条命令检查脚本和 Hugo 构建。后两条命令生成生产站点、创建搜索索引，并检查内部链接。
