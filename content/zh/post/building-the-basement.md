这个站点基于 Hugo 和 `hugo-brewm` 主题。本地模板、样式、内容和配置在需要时会覆盖主题实现，主题子模块保持固定版本。本文记录站点的主要导航、响应式布局、复用数据、搜索集成和构建检查。

## 首页与主菜单

首页使用文字 Logo，因此不需要分别准备浅色和深色图片。主菜单包含三个入口：

- `Posts` 打开文章索引。
- `About` 打开介绍页面。
- `GitHub` 打开外部个人主页。

首页还包含三个精选入口的轮播、站点介绍和最近文章。分类封面提供第二种浏览方式。保留文章列表和分类导航后，读者既可以查看最近更新，也可以按主题浏览。

轮播曾在一次清理中删除，后来以更窄的用途恢复。它现在只链接少量精选入口，不再重复完整导航。

## 主题变量与响应式行为

主题通过 CSS 变量定义浅色、深色、对比度和调色板配置。页面背景与文字主要使用 `--bg`、`--fg`、`--mid` 和 `--ac`。切换配色或对比度时，这些变量会更新，组件不需要维护另一套样式。

正文排版继续使用主题配置。目录标签、日期、正文和代码块保持原有层级，本地样式不引入额外字体或卡片体系。

窄屏下页面变为单栏。站名保持可见，主菜单收进现有导航控件，装饰图片不再占据文章标题区域。只适合宽屏的内容不会放进移动端首屏。

## 页脚内容

页脚区块是独立内容文件，并设置：

```yaml
type: footer
headless: true
```

这样正文可以进入页脚，同时不会生成普通独立页面。当前页脚链接到较大的 Neuro-sama 档案和公开主页。

主菜单保持较短。分类页和文章索引负责按主题浏览，搜索框负责直接查找。

## Pagefind 搜索

Hugo 生成生产站点后，由 Pagefind 建立搜索索引：

```bash
npm run build:search
```

该命令执行 `pagefind --site public`。`type: post` 的页面提供 `data-pagefind-body` 区域并进入索引，关于页和工具页不进入索引。

搜索控件放在主菜单中，因此阅读长文章时仍可直接调用。

## 评论配置

站点配置关闭了评论。当前没有配置 Giscus 仓库或 Fediverse 讨论地址，文章模板也不会输出空的评论区。

以后恢复评论时，每篇文章应指向真实的讨论地址，不使用没有关联的通用表单。

## 构建检查

修改布局或导航后，在发布前执行：

```bash
npm run check
npm run build
npm run check:links
```

这些命令检查 JavaScript 和 Hugo 输出、生成 Pagefind 索引，并检查生成站点中的内部链接。
